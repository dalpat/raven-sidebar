3. What today's rebuild changed

Three commits. The core one, 5c94aa2, is 23 files, +156 / −486 — it deletes far more styling than it adds, because a hand-rolled palette was replaced with system-theme primitives.

ChangeWhy
Removed the blur Sidebar.js Shell.BlurEffect in BACKGROUND mode re-samples the framebuffer every frame; it shakes/flickers at the Mutter level and can't be stabilised from an extension. The translucent themed surface stands in for it.
Dropped the manual pin ThemeBar.js, ThemeManager.js Deleted the Light/Dark/Auto strip and the theme gsetting (~270 lines). The sidebar follows the system instead of being pinned by hand.
No hardcoded colours, no gradients every widget Panel reuses popup-menu-content; text inherits the themed foreground; accents use -st-accent-color; subtle fills use st-transparentize(...). Every literal rgba()/#hex and every gradient was removed.
Themed slider SliderBar.js The Cairo paint can't read CSS, so a hidden probe carries -st-accent-color and the paint reads the resolved accent + foreground from the theme node.
Survives theme reloads StyleManager.js GNOME rebuilds its StTheme on a light/dark switch and drops externally-loaded stylesheets. StyleManager now re-applies on ThemeContext::changed, so styles don't vanish mid-switch.

The widget set from the glass commit (Now Playing, Quick Toggles, Power/Battery, Battery Health, Habit Tracker, IP, plus the shared Network/Power services) is unchanged — only their styling was reworked.

4. Theme behaviour & one known limitation BY DESIGN

The sidebar follows the GNOME shell theme: it goes light only when color-scheme = prefer-light, matching GNOME's own Quick Settings and calendar popups.

  • The system dark-mode pill does not flip it to light. The pill only toggles between prefer-dark and default, and GNOME Shell renders default as dark chrome — so the whole shell (ours included) stays dark. Only an explicit prefer-light is a light shell.
  • This was a deliberate choice ("option A"): match the shell with zero defined colours. Making the pill flip the sidebar would mean following the app preference and defining our own light surface (the shell offers none for default) — deferred for now.
